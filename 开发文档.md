# Noctalia 插件开发文档：icefish/phone-operate

> 基于 scrcpy 的手机操控插件，通过 Noctalia 桌面壳的插件系统提供图形化启动、参数配置、多设备管理能力。
> 所有投屏/控制能力对接 scrcpy 原生 CLI 接口，插件本身只做"启动管理 + 参数传递 + 状态展示"。

---

## 0. 文档约定

- 目标插件 id：`icefish/phone-operate`
- 目标 Noctalia 版本：v5+（plugin_api = 24，见 §3.1 说明）
- 依赖外部命令：`scrcpy`、`adb`
- 配置目录：`$XDG_DATA_HOME/noctalia/plugins/phone-operate/`（开发期）或 git/path source
- 插件数据目录：`noctalia.pluginDataDir()` 返回的路径（持久化参数、历史设备）

---

## 1. 架构总览

### 1.1 分层

```
┌──────────────────────────────────────────────────┐
│  Noctalia 插件层（Luau）                          │
│  ┌──────────────┐  ┌──────────────┐             │
│  │ bar widget   │  │   panel      │  launcher   │
│  │ (状态图标)    │  │ (主力配置UI) │  provider    │
│  └──────┬───────┘  └──────┬───────┘             │
│         │                 │                      │
│         ▼                 ▼                      │
│  ┌──────────────────────────────────┐           │
│  │        service (后台)              │           │
│  │  - adb devices 轮询                │           │
│  │  - 历史 IP 自动 connect            │           │
│  │  - scrcpy 进程管理                  │           │
│  │  - 参数持久化读写                    │           │
│  └────────────┬─────────────────────┘           │
└────────────────┼─────────────────────────────────┘
                 │ noctalia.runAsync / runStream
                 ▼
┌──────────────────────────────────────────────────┐
│  外部命令层                                        │
│  adb devices / adb connect / adb pair             │
│  scrcpy --max-size N --video-bit-rate N ...       │
│  pkill -f "scrcpy.*<device-id>"                   │
└──────────────────────────────────────────────────┘
                 │
                 ▼
┌──────────────────────────────────────────────────┐
│  手机端                                            │
│  scrcpy-server (Java, 推送到设备)                 │
│  H.264 视频流 + 控制通道 + 音频                    │
└──────────────────────────────────────────────────┘
```

### 1.2 核心设计原则

1. **插件零渲染开销**：scrcpy 的视频解码/渲染全部在 scrcpy 自己的 SDL 窗口里，插件不碰视频流
2. **所有对接走 scrcpy 原生 CLI 参数**：插件只是参数组装器 + 进程启动器，不重新实现 scrcpy 协议
3. **进程管理靠 PID 追踪 + pkill**：noctalia.runAsync 是 fire-and-forget，拿不到进程句柄；通过记录 PID 和定向 pkill 管理
4. **参数持久化到 pluginDataDir**：每台设备独立记住参数偏好
5. **状态在 entries 间通过 noctalia.state 流转**：service 发布设备状态，widget/panel 订阅

## 3. Manifest（plugin.toml）

### 3.1 plugin_api 版本选择

需要的能力与对应最低 API level：
| 能力 | API level | 来源 |
|---|---|---|
| 基础 entries + settings | 3 | manifest 文档 |
| 模块 require | 22 | entries 文档 "plugin_api = 22" |
| onConfigChanged (service) | 17 | entries 文档 |

取最大值 → **plugin_api = 22**。

> 历史决策变更：初版曾选 plugin_api = 24 以使用 `noctalia.runAsync` 的参数数组形式（direct-argv）安全传递用户输入。
> 但 direct-argv 在 plugin-api-data 中 `noctaliaVersion = null`（未发布），Noctalia v5.0.0（beta.8）最高仅支持到 level 23，导致插件 API 不兼容。
> 故改为字符串形式（走 `/bin/sh -c`，level 3 起支持），用户输入经 `lib/shell.luau` 的 `shell.quote` 单引号转义防注入，降级到已发布的 plugin_api = 22（仅需 module-require）。

### 3.3 settings 设计要点

- 插件级 settings（上表）是"默认值"，每台设备可覆盖（见 §6 持久化）
- panel 读取设备特定参数优先，fallback 到插件级 settings
- `bit_rate` 用 int（Mbps），命令组装时加 "M" 后缀：`--video-bit-rate 8M`（scrcpy 3.0+ 命名，旧版 `--bit-rate` 已废弃）
- `poll_interval_ms` 控制 service 轮询频率，默认 3s

## 4. Entry 脚本设计

### 4.1 state 模型（lib/state.luau）

entries 间不共享 Lua 内存，通过 `noctalia.state` 交换。定义统一的 state keys：

```luau
-- lib/state.luau
local M = {}

-- 设备列表 key：service 发布，widget/panel/launcher 订阅
-- 值结构：{ {id="192.168.1.3:5555", label="Mi 14", transport="wifi", online=true, scrcpy_pid=nil}, ... }
M.KEY_DEVICES = "devices"

-- 当前活动设备 id（最后操作的那台）
M.KEY_ACTIVE = "active_device"

-- scrcpy 运行状态：{ "<device_id>" = <pid_or_nil>, ... }
M.KEY_RUNNING = "running"

return M
```

### 4.2 service.luau（后台核心）

职责：
1. 启动时加载历史设备列表，自动尝试 adb connect
2. 定期轮询 `adb devices`，刷新设备列表
3. 提供 IPC 接口供 panel/widget 调用：start/stop/connect/pair/disconnect
4. 管理 scrcpy 进程生命周期

```luau
-- service.luau
local persistence = require("./lib/persistence.luau")
local adb = require("./lib/adb.luau")
local scrcpy = require("./lib/scrcpy.luau")
local state = require("./lib/state.luau")
local models = require("./lib/models.luau")

local devices = {}     -- 当前设备列表（内存模型）
local running = {}     -- device_id -> pid
local networkReady = false
local pendingRetries = {}  -- device_id -> {attempts=0, timers={}}

-- ─── 启动：加载历史 + 自动 connect（带延迟重试 + 网络监听）───
-- 顶层代码在加载时运行一次
local history = persistence.loadHistory()

-- 先检查网络是否就绪（WiFi/以太网是否拿到 IP）
local function checkNetworkAsync(cb)
    noctalia.runAsync({ "sh", "-c", "ip -4 addr show | grep -q 'inet ' && echo ok || echo no" }, function(result)
        local ok = result.exitCode == 0 and result.stdout:match("ok") ~= nil
        cb(ok)
    end)
end

-- 延迟重试 connect：最多 3 次，间隔 5s / 10s / 20s
local function retryConnect(device_id, label, attempt)
    attempt = attempt or 1
    if attempt > 3 then
        noctalia.notify("Phone Operate", "无法连接 " .. label .. "，3 次重试均失败，请确认手机在线")
        return
    end
    local delays = { [1]=5, [2]=10, [3]=20 }
    noctalia.runAsync({ "sleep", tostring(delays[attempt]) }, function()
        adb.connectAsync(device_id, function(ok)
            if ok then
                refreshDevices()
                noctalia.log("重试连接成功: " .. device_id .. " (第 " .. attempt .. " 次)")
            else
                retryConnect(device_id, label, attempt + 1)
            end
        end)
    end)
end

-- 自动 connect 入口
local function autoConnect(entry)
    if entry.transport ~= "wifi" then return end
    adb.connectAsync(entry.id, function(ok)
        if ok then
            refreshDevices()
        else
            -- 失败：启动延迟重试
            retryConnect(entry.id, entry.label, 1)
        end
    end)
end

-- 网络监听：每 5s 检查一次，状态从断开->就绪时重新触发自动 connect
local lastNetState = nil
local function monitorNetwork()
    noctalia.runAsync({ "sh", "-c", "ip -4 addr show | grep -q 'inet ' && echo ok || echo no" }, function(result)
        local ok = result.exitCode == 0 and result.stdout:match("ok") ~= nil
        if lastNetState == false and ok then
            -- 网络从断开恢复为可用：重新触发自动 connect
            noctalia.log("网络恢复，重新尝试自动连接")
            for _, entry in ipairs(history) do
                autoConnect(entry)
            end
        end
        lastNetState = ok
    end)
end

-- 启动时：先检查网络，就绪则自动 connect，否则等网络恢复
checkNetworkAsync(function(netOk)
    if netOk then
        for _, entry in ipairs(history) do
            autoConnect(entry)
        end
    else
        noctalia.log("网络未就绪，等待网络恢复后自动连接")
    end
end)

noctalia.setUpdateInterval(noctalia.getConfig("poll_interval_ms"))
refreshDevices()

-- ─── 周期更新：轮询 adb devices + 网络监听 ───
local netCheckCounter = 0
function update()
    refreshDevices()
    -- 每 5 个轮询周期检查一次网络状态（约 15s，取决于 poll_interval_ms）
    netCheckCounter = netCheckCounter + 1
    if netCheckCounter >= 5 then
        monitorNetwork()
        netCheckCounter = 0
    end
end

-- 当用户改设置时，不重启 service，只更新轮询间隔
function onConfigChanged()
    noctalia.setUpdateInterval(noctalia.getConfig("poll_interval_ms"))
end

-- ─── 设备列表刷新 ───
function refreshDevices()
    adb.listDevicesAsync(function(adbDevices)
        -- adbDevices: { {serial="...", state="device", transport="usb"/"wifi", model="25091RP04C"} }
        local merged = mergeWithHistory(adbDevices)
        -- 为每台设备生成 label：用户自定义名称 > 原始型号
        for _, dev in ipairs(merged) do
            local customName = persistence.loadName(dev.id)
            dev.label = models.label(dev.model, customName)
        end
        devices = merged
        noctalia.state.set(state.KEY_DEVICES, devices)
    end)
end

-- ─── 录屏文件清理：超过最大保留数则删最旧的 ───
function cleanupRecordings()
    local maxFiles = noctalia.getConfig("record_max_files") or 10
    local dir = noctalia.pluginDataDir()
    noctalia.runAsync({ "sh", "-c", string.format(
        "ls -1t %s/rec_*.mp4 2>/dev/null | tail -n +%d | xargs -r rm -f",
        dir, maxFiles + 1
    ) }, function(result)
        if result.exitCode ~= 0 and result.stderr ~= "" then
            noctalia.log("录屏清理异常: " .. result.stderr)
        end
    end)
end

-- ─── IPC 接口（panel/widget 通过 noctalia msg plugin ... 调用）───
function onIpc(event, payload)
    if event == "start" then
        local dev = findDevice(payload.device_id)
        local params = persistence.loadParams(payload.device_id)
        local pid = scrcpy.start(dev, params)
        running[payload.device_id] = pid
        noctalia.state.set(state.KEY_RUNNING, running)
        -- 如果录屏开启，启动后触发清理（删旧文件）
        if params.record then
            cleanupRecordings()
        end
    elseif event == "stop" then
        scrcpy.stop(payload.device_id)
        running[payload.device_id] = nil
        noctalia.state.set(state.KEY_RUNNING, running)
    elseif event == "restart_with_params" then
        -- 用户在 panel 改了参数：杀掉旧进程，用新参数重启
        scrcpy.stop(payload.device_id)
        local params = payload.params
        persistence.saveParams(payload.device_id, params)
        local pid = scrcpy.start(findDevice(payload.device_id), params)
        running[payload.device_id] = pid
        noctalia.state.set(state.KEY_RUNNING, running)
    elseif event == "connect" then
        adb.connectAsync(payload.address, function(ok)
            if ok then persistence.addHistory(payload.address, payload.label, "wifi") end
            refreshDevices()
        end)
    elseif event == "pair" then
        adb.pairAsync(payload.address, payload.code, function(ok)
            if ok then noctalia.notify("Phone Operate", "配对成功") end
        end)
    elseif event == "disconnect" then
        adb.disconnect(payload.device_id)
        refreshDevices()
    elseif event == "usb_mode" then
        adb.usbMode(payload.device_id)
        refreshDevices()
    elseif event == "rename" then
        persistence.saveName(payload.device_id, payload.name)
        refreshDevices()
    end
end

function onExit(_signal, reason)
    -- 插件禁用/卸载/重载时：不杀 scrcpy（用户的投屏不应被打断）
    -- 但如果 reason == "uninstall"，提示用户手动关 scrcpy
    if reason == "uninstall" then
        noctalia.notify("Phone Operate", "插件已卸载，正在运行的 scrcpy 窗口请手动关闭")
    end
end
```

### 4.3 widget.luau（bar widget 状态图标）

```luau
-- widget.luau
local state = require("./lib/state.luau")

local running = false

-- 订阅 service 发布的运行状态（KEY_RUNNING）
-- 语义：绿 = 正在投屏（至少一台 scrcpy 运行中），灰 = 未投屏
noctalia.state.watch(state.KEY_RUNNING, function(run)
    -- run 是 { device_id = pid } 表
    local any = false
    for _ in pairs(run) do any = true; break end
    running = any
    renderWidget()
end)

function renderWidget()
    if running then
        barWidget.setGlyph("device-mobile")
        barWidget.setGlyphColor("green")
        barWidget.setTooltip("Phone Operate: 正在投屏")
    else
        barWidget.setGlyph("device-mobile")
        barWidget.setGlyphColor("surface_variant")
        barWidget.setTooltip("Phone Operate: 未投屏")
    end
end

function onClick()
    noctalia.togglePanel("icefish/phone-operate:main")
end

function onRightClick()
    -- 右键：若有设备且未运行，直接用最近设备 + 历史参数启动
    if not running then
        local devs = noctalia.state.get(state.KEY_DEVICES) or {}
        if #devs > 0 then
            noctalia.runAsync({ "noctalia", "msg", "plugin", "icefish/phone-operate:core", "all", "start", '{"device_id":"' .. devs[1].id .. '"}' })
        end
    end
end
```

### 4.4 panel.luau（主力配置 UI）

用完即关弹窗，declarative UI 构建。包含：设备列表、参数配置、启动/停止、配对、断开。

```luau
-- panel.luau
local state = require("./lib/state.luau")
local persistence = require("./lib/persistence.luau")

local devices = {}
local selectedDevice = nil   -- 当前选中的 device_id
local params = {}            -- 当前选中设备的参数
local renameDev = nil        -- 正在重命名的 device_id
local renameVal = ""        -- 重命名输入框当前值

-- 订阅设备列表
noctalia.state.watch(state.KEY_DEVICES, function(d)
    devices = d
    if not selectedDevice and #devices > 0 then
        selectedDevice = devices[1].id
        params = persistence.loadParams(selectedDevice)
    end
    render()
end)

function onOpen()
    devices = noctalia.state.get(state.KEY_DEVICES) or {}
    if #devices > 0 then
        selectedDevice = selectedDevice or devices[1].id
        params = persistence.loadParams(selectedDevice)
    end
    render()
end

function render()
    local rows = {}

    -- ─── 设备选择区 ───
    for _, dev in ipairs(devices) do
        local isSel = (dev.id == selectedDevice)
        local isRenaming = (renameDev == dev.id)

        if isRenaming then
            -- 重命名模式：label 位置直接变成输入框，inline 编辑
            table.insert(rows, ui.row({
                key = "dev-" .. dev.id,
                gap = 8, align = "center",
            }, {
                ui.glyph({ name = dev.transport == "wifi" and "wifi" or "usb", size = 16 }),
                ui.input({ key = "rename-input-" .. dev.id, value = renameVal,
                           placeholder = dev.model or dev.id,
                           onChange = "onRenameInput",
                           onSubmit = "onRenameSubmit", flexGrow = 1 }),
                ui.button({ glyph = "check", variant = "primary", controlSize = "sm",
                            tooltip = "确认", onClick = "onRenameSubmit" }),
                ui.button({ glyph = "x", variant = "ghost", controlSize = "sm",
                            tooltip = "取消", onClick = function()
                    renameDev = nil; renameVal = ""; render()
                end }),
            }))
        else
            -- 正常模式：显示 label，双击或点 edit 按钮进入重命名
            table.insert(rows, ui.row({
                key = "dev-" .. dev.id,
                gap = 8, align = "center",
                onClick = function()
                    selectedDevice = dev.id
                    params = persistence.loadParams(dev.id)
                    render()
                end,
                onRightClick = function()
                    -- 右键设备行直接进入 inline 重命名
                    renameDev = dev.id
                    renameVal = persistence.loadName(dev.id) or ""
                    render()
                end,
            }, {
                ui.glyph({ name = dev.transport == "wifi" and "wifi" or "usb", size = 16 }),
                ui.label({ text = dev.label, flexGrow = 1 }),
                -- edit 按钮：点击也进入 inline 重命名
                ui.button({ glyph = "edit", variant = "ghost", controlSize = "sm",
                            tooltip = "重命名", onClick = function()
                    renameDev = dev.id
                    renameVal = persistence.loadName(dev.id) or ""
                    render()
                end }),
                ui.box({ width = 12, height = 12, radius = 6,
                         fill = dev.online and "green" or "surface_variant" }),
                isSel and ui.glyph({ name = "check", size = 16 }) or ui.spacer({}),
            }))
        end
    end

    if #devices == 0 then
        table.insert(rows, ui.label({ text = "未发现设备，先配对或连接", color = "surface_variant" }))
    end

    -- ─── 参数区（仅当选中设备时显示）───
    if selectedDevice then
        table.insert(rows, ui.separator({ thickness = 1, spacing = 8 }))

        -- 分辨率
        table.insert(rows, ui.row({ gap = 8, align = "center" }, {
            ui.label({ text = "分辨率上限", width = 80 }),
            ui.slider({ min = 256, max = 4096, step = 64,
                        value = params.max_size or 1920,
                        onChange = function(v)
                params.max_size = tonumber(v)
                persistence.saveParams(selectedDevice, params)
                -- 立即重启 scrcpy（如果正在运行）
                ipcRestartWithParams()
                render()
            end, flexGrow = 1 }),
            ui.label({ text = tostring(params.max_size or 1920), width = 50 }),
        }))

        -- 码率
        table.insert(rows, ui.row({ gap = 8, align = "center" }, {
            ui.label({ text = "码率 Mbps", width = 80 }),
            ui.slider({ min = 1, max = 100, step = 1,
```

### 5.2 lib/adb.luau

```luau
-- lib/adb.luau
local M = {}
local models = require("./lib/models.luau")
-- 输出示例：
--   cf56f01f               device usb:5-1 product:piano model:25091RP04C
--   192.168.1.3:5555       device product:piano
function M.listDevicesAsync(cb)
    noctalia.runAsync({ "adb", "devices", "-L" }, function(result)
        local out = {}
        if result.exitCode == 0 then
            for line in result.stdout:gmatch("[^\n]+") do
                -- 跳过 "List of devices attached" 标题
                if not line:match("^List of devices") and not line:match("^%s*$") then
                    local serial, state = line:match("^(%S+)%s+(%S+)")
                    if serial and state == "device" then
                        local transport = line:match("usb:") and "usb" or "wifi"
                        local model = line:match("model:(%S+)") or serial
                        -- customName 由 service 层从 persistence 加载后合并进 device 对象
                        -- 这里只填原始 model，label 由 service 层调用 models.label() 生成
                        table.insert(out, {
                            id = serial,
                            state = state,
                            transport = transport,
                            model = model,      -- 原始型号
                            online = true,
                        })
                    end
                end
            end
        end
        cb(out)
    end)
end

-- adb connect IP:PORT
function M.connectAsync(address, cb)
    noctalia.runAsync({ "adb", "connect", address }, function(result)
        -- 输出 "connected to ..." 或 "already connected" 算成功
        local ok = result.exitCode == 0 and
            (result.stdout:match("connected") ~= nil)
        cb(ok, result.stdout)
    end)
end

-- adb pair IP:PORT，然后通过 stdin 输入配对码
function M.pairAsync(address, code, cb)
    -- adb pair 是交互式的，需要用 runStream 喂配对码
    -- 但 runStream 不支持 stdin 写入；改用 shell 命令 echo | adb pair
    local cmd = string.format("echo '%s' | adb pair %s", code, address)
    noctalia.runAsync(cmd, function(result)
        local ok = result.exitCode == 0 and result.stdout:match("successfully") ~= nil
        cb(ok, result.stdout)
    end)
end

-- adb disconnect
function M.disconnect(device_id)
    noctalia.runAsync({ "adb", "disconnect", device_id })
end

-- adb -s <id> usb
function M.usbMode(device_id)
    noctalia.runAsync({ "adb", "-s", device_id, "usb" })
end

return M
```

**注意**：`adb pair` 的交互式输入是个难点。`noctalia.runAsync` 不支持 stdin 写入。上面用 shell 管道 `echo | adb pair` 绕过，但这要求配对码不含特殊字符（6 位数字，安全）。如果未来 Noctalia 支持 stdin 写入或 PTY，可改为更稳的方案。

### 5.3 lib/scrcpy.luau

```luau
-- lib/scrcpy.luau
local M = {}

-- 组装 scrcpy 命令（参数数组形式，安全传递用户输入）
function M.buildArgs(device, params)
    local args = { "scrcpy" }

    -- 指定设备
    table.insert(args, "-s")
    table.insert(args, device.id)

    -- 分辨率上限
    if params.max_size then
        table.insert(args, "--max-size")
        table.insert(args, tostring(params.max_size))
    end

    -- 码率（用户输入 Mbps，转为 "8M" 格式；scrcpy 3.0+ 用 --video-bit-rate）
    if params.bit_rate then
        table.insert(args, "--video-bit-rate")
        table.insert(args, tostring(params.bit_rate) .. "M")
    end

    -- 帧率上限
    if params.max_fps then
        table.insert(args, "--max-fps")
        table.insert(args, tostring(params.max_fps))
    end

    -- 熄屏投屏
    if params.turn_screen_off then
        table.insert(args, "--turn-screen-off")
    end

    -- 录屏（文件名带时间戳，存到 pluginDataDir）
    if params.record then
        local dir = noctalia.pluginDataDir()
        local ts = os.date("%Y%m%d_%H%M%S")
        table.insert(args, "--record")
        table.insert(args, dir .. "/rec_" .. ts .. ".mp4")
    end

    return args
end

-- 启动 scrcpy，返回 PID
function M.start(device, params)
    local args = M.buildArgs(device, params)
    -- fire-and-forget：runAsync 不带 callback，不捕获输出
    noctalia.runAsync(args)

    -- 问题：runAsync 不返回 PID
    -- 解决：启动后立即用 pgrep 查 PID（scrcpy 进程刚启动，pgrep 能找到）
    -- 但这是异步的；这里先返回 nil，PID 追踪靠 service 周期性更新
    -- 更好的方案：用 shell 命令记录 PID
    -- scrcpy ... & echo $! > /tmp/phone-operate_<device>.pid
    -- 但参数数组形式不支持 shell 语法

    -- 实际方案：启动后用 runAsync 查 pgrep
    noctalia.runAsync({ "pgrep", "-f", "scrcpy.*" .. device.id }, function(result)
        if result.exitCode == 0 then
            local pid = tonumber(result.stdout:match("(%d+)"))
            if pid then
                -- 通过 state 发布 PID
                -- 注意：这里在模块函数里，不能直接 set state；
                -- PID 追踪由 service 层在调用后处理
            end
        end
    end)

    return nil  -- PID 异步获取，service 负责
end

-- 停止指定设备的 scrcpy
function M.stop(device_id)
    -- 用 pkill 精确匹配：scrcpy 命令行里包含 device_id
    noctalia.runAsync({ "pkill", "-f", "scrcpy.*" .. device_id })
end

return M
```

**PID 追踪的关键限制**：
`noctalia.runAsync` 是 fire-and-forget，不返回进程句柄或 PID。这导致无法精确 kill 某个 scrcpy 进程。当前方案用 `pkill -f "scrcpy.*<device_id>"` 匹配命令行，依赖 scrcpy 启动参数里包含 `-s <device_id>`。**风险**：如果 device_id 是 IP:端口 格式且正好在其他进程命令行里出现，会误杀。缓解：匹配更完整的模式 `scrcpy.*-s <device_id>`，并在 service 层维护一个"运行中设备"集合，stop 时先查是否真在运行。

**更优的 PID 方案（备选）**：
若 Noctalia 未来支持 `noctalia.runAsync(argv, { trackPid = true })` 或类似，直接用。当前版本下，可改用 shell 字符串形式启动并写 PID 文件：
```luau
local cmd = string.format("scrcpy -s %s --max-size %d ... & echo $! > /tmp/phone-operate_%s.pid",
    device.id, params.max_size, safeId)
noctalia.runAsync(cmd)  -- shell 形式，支持 & 和 $!
```
代价是失去参数数组的安全转义，需要自己 shell-quote。device.id 是 IP:端口或序列号，基本安全，但要在文档里标注。

```luau
-- lib/persistence.luau
local M = {}

local function dataFile()
    return noctalia.pluginDataDir() .. "/data.json"
end

local function loadAll()
    local raw = noctalia.readFile(dataFile())
    if raw then
        local t, err = noctalia.json.decode(raw)
        if t then return t end
    end
    return { devices = {}, params = {} }
end

local function saveAll(data)
    noctalia.writeFile(dataFile(), noctalia.json.encode(data))
end

-- 历史设备：{ {id, label, transport}, ... }
function M.loadHistory()
    return loadAll().devices or {}
end

function M.addHistory(address, label, transport)
    local data = loadAll()
    -- 去重
    for _, d in ipairs(data.devices) do
        if d.id == address then return end
    end
    table.insert(data.devices, { id = address, label = label, transport = transport })
    saveAll(data)
end

function M.removeHistory(address)
    local data = loadAll()
    for i, d in ipairs(data.devices) do
        if d.id == address then table.remove(data.devices, i); break end
    end
    saveAll(data)
end

-- 每设备参数：{ ["192.168.1.3:5555"] = { max_size=1920, bit_rate=8, ... }, ... }
function M.loadParams(device_id)
    local data = loadAll()
    -- fallback 到插件级 settings 默认值
    local fallback = {
        max_size = noctalia.getConfig("max_size"),
        bit_rate = noctalia.getConfig("bit_rate"),
        max_fps = noctalia.getConfig("max_fps"),
        turn_screen_off = noctalia.getConfig("turn_screen_off"),
        record = noctalia.getConfig("record"),
    }
    return data.params and data.params[device_id] or fallback
end

function M.saveParams(device_id, params)
    local data = loadAll()
    data.params = data.params or {}
    data.params[device_id] = params
    saveAll(data)
end

-- 每设备自定义名称：{ ["192.168.1.3:5555"] = "我的手机", ... }
function M.loadName(device_id)
    local data = loadAll()
    return data.names and data.names[device_id] or nil
end

function M.saveName(device_id, name)
    local data = loadAll()
    data.names = data.names or {}
    if name and name ~= "" then
        data.names[device_id] = name
    else
        data.names[device_id] = nil  -- 清空则删 key
    end
    saveAll(data)
end

return M
```

## 6. 进程管理与多设备策略

### 6.1 多设备多开

用户明确要求"支持同时多开几个 scrcpy 窗口"。策略：
- service 维护 `running = { device_id -> pid }` 表
- 每台设备独立启动 scrcpy，互不干扰
- 启动新设备时不杀旧的
- panel 的"停止"按钮只停当前选中设备的 scrcpy

### 6.2 运行中改参数 = 自动重启

用户确认的交互：运行中改参数 → 杀掉当前 scrcpy → 带新参数重开。
- panel 的每个参数 onChange 回调里调 `ipcRestartWithParams()`
- service 收到 `restart_with_params` 事件：先 stop，再 start with new params
- 短暂闪屏是 scrcpy 窗口关闭再打开的必然结果，无法避免

### 6.3 进程清理

- `onExit` 不杀 scrcpy（投屏不应被插件卸载打断，除非 uninstall）
- service 周期性校验 `running` 表里的 PID 是否还活着（pgrep），清理僵尸记录
- 提供"全部停止"入口（panel 里可加，或 widget 右键）

### 7.3 窗口透明度

### 7.4 窗口尺寸

用户确认：窗口尺寸由 niri 管理（Mod+右键拖边缘缩放，Mod+左键拖动移动），插件不传 `--window-width/height`。scrcpy 的 `--max-size` 管视频流分辨率，窗口显示大小由 niri/用户控制。

## 8. 自动设备发现策略

### 8.1 三层发现

1. **adb devices 轮询**（service 周期执行）：列出所有 USB + 已 connect 的无线设备
2. **历史 IP 自动 connect**（启动时执行）：从 pluginDataDir 读历史无线地址，逐个 adb connect
3. **手动新增**：panel 的"配对"和"连接"入口处理新设备

### 8.2 网络扫描的不可行性

用户原始需求提到"自动查找可以连接的手机"。需明确：
- adb 无法扫描局域网发现新设备
- mDNS 自动发现需要 adb 支持 mDNS（`adb mdns services`），当前系统 adb（1.0.41）不支持（已验证）
- 因此"自动查找"上限 = adb devices + 历史自动 connect，未知设备仍需手动
- 若用户换官方 platform-tools（AUR: android-platform-tools 或 Google 解压版），可扩展 mDNS 发现，作为 v0.2 的可选增强

## 9. IPC 通信约定

panel/widget/launcher → service 的 IPC 调用格式：

```
noctalia msg plugin icefish/phone-operate:core all <event> <json_payload>
```

事件清单：
| event | payload | 说明 |
|---|---|---|
| `start` | `{device_id}` | 启动指定设备的 scrcpy |
| `stop` | `{device_id}` | 停止指定设备的 scrcpy |
| `restart_with_params` | `{device_id, params}` | 改参数后重启 |
| `connect` | `{address, label}` | 连接无线设备 |
| `pair` | `{address, code}` | 配对新设备 |
| `disconnect` | `{device_id}` | 断开无线设备 |
| `usb_mode` | `{device_id}` | 切回 USB 模式 |
| `rename` | `{device_id, name}` | 修改设备自定义名称（空串=恢复原始型号） |

注意：IPC payload 是 JSON 字符串，service 的 onIpc 需 `noctalia.json.decode(payload)` 解析。

   ```sh
   noctalia msg plugin icefish/phone-operate:core all start '{"device_id":"cf56f01f"}'
   ```

5. **查看日志**：
   插件脚本里 `noctalia.log(msg)` 写入 Noctalia 日志，开发期可 `journalctl --user -u noctalia -f` 或 Noctalia 的日志面板查看

## 11. 已知限制与技术债

### 11.1 scrcpy 参数不支持运行中热改
`--max-size`、`--video-bit-rate`、`--max-fps`、`--turn-screen-off`、`--record` 全部是启动参数，运行中改必须重启 scrcpy。当前方案：改参数 → 自动 stop + start，有短暂闪屏。

### 11.2 PID 追踪困难
`noctalia.runAsync` 不返回 PID。当前用 `pkill -f` 匹配命令行，有误杀风险。详见 §5.2。若 Noctalia 未来支持进程句柄，应迁移。

### 11.3 adb pair 交互式输入
`adb pair` 需要交互式输入配对码，`noctalia.runAsync` 不支持 stdin 写入。当前用 `echo | adb pair` shell 管道绕过，仅限配对码为纯数字（6 位）时安全。

### 11.4 mDNS 自动发现不可用
当前系统 adb 不支持 mDNS（已验证），无法自动发现局域网内未知无线设备。需换官方 platform-tools 才能启用，作为未来增强。

### 11.5 配对端口 vs 调试端口
用户易混淆。配对端口是一次性的（adb pair 用），调试端口是长期连接用（adb connect/scrcpy 用）。panel 的配对流程需明确提示用户区分两个端口。

### 11.6 无线调试端口变化
Android 11+ 无线调试若开"随机端口"，重启后端口会变。插件记住的历史地址可能失效。缓解：connect 失败时提示用户去手机查新端口，更新历史记录。

## 13. 设计决议（已确认）

以下 5 个问题已与用户确认，按决议实施：

1. **设备 label 来源**：用户可自行修改设备名称，不预设映射表。
   显示优先级：用户自定义名称 > 原始型号（adb 输出的 model 字段）。
   未自定义时显示原始型号如 `25091RP04C`，自定义后显示用户设置的名称。
   自定义名称持久化到 pluginDataDir，按设备 id 存取（loadName/saveName）。
   panel 提供重命名入口（edit 按钮 + 输入框，留空恢复原始型号）。详见 §5.1 和 §5.4。

2. **录屏文件管理**：加清理机制，用户可设置最大保留视频数量（默认 10 个）。
   新增插件级 setting `record_max_files`，service 在每次启动录屏后触发清理，
   超过上限时删除最旧的文件。详见 §4.2 的 `cleanupRecordings()`。

3. **多开窗口的 niri 窗口规则**：不加错开规则。
   涉及窗口管理的全部交给 niri，包括多窗口重叠。插件不干预。

4. **service 启动时网络未就绪的自动 connect 失败处理**：延迟重试，最多 3 次 + 监听网络。
   首次自动 connect 失败后，间隔递增重试（5s / 10s / 20s），3 次全败则放弃并通知用户。
   同时监听网络状态变化（通过轮询 `ip addr` 或 `nmcli` 判断网络是否就绪），
   网络从断开恢复为可用时重新触发自动 connect。详见 §4.2 的 `retryConnect()`。

5. **bar widget 状态语义**：绿 = 正在投屏（至少一台 scrcpy 运行中），灰 = 未投屏。
   注意：不是"有无设备"，而是"是否正在投屏"。
   widget 订阅 `state.KEY_RUNNING`（非空=绿 / 空=灰），而非 `KEY_DEVICES`。

### 使用约定

- 脚本里所有面向用户的字符串必须通过 `noctalia.tr(key)` 或 `noctalia.tr(key, subst)` 获取，不硬编码
- manifest 的 label_key / description_key 对应翻译文件里的 key
- `subst` 用于带变量的消息，如 `noctalia.tr("notify.connect_failed", { name = dev.label })`
- Noctalia 根据系统语言自动选择翻译文件，中文环境用 zh.json，其他用 en.json fallback
- 注意：Noctalia 内部解析出的语言代码可能是 `zh-Hans`（从 `zh-CN` 派生），此时它按
  `translations/zh-Hans.json` 查找；若只有 `zh.json` 会匹配不上并回退到英文。
  因此仓库同时维护 `zh.json`（约定名）与 `zh-Hans.json`（运行时解析名），两者内容相同，
  修改翻译时需同步两份。
