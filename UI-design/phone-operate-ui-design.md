# 手机操控（Phone Operate）UI 设计方案

> 插件 `icefish/phone-operate` 界面重设计 · 配套可交互原型见 `prototype.html`
> 设计目标：**美观 · 易用 · 简洁**，符合 Noctalia / niri 桌面壳用户的使用习惯

---

## 1. 设计上下文

| 维度 | 说明 |
|---|---|
| **目标用户** | Noctalia 桌面壳的高级用户 / 开发者，熟悉 scrcpy、ADB、IP:端口、码率等技术概念 |
| **使用场景** | 本地桌面中快速管理 **1～多台** Android 手机的投屏：启动/停止、按设备调参、配对新设备、切回 USB、改名 |
| **载体约束** | 三个 UI 面：`bar widget`（状态图标）、`panel`（380×520 悬浮主配置窗）、`launcher_provider`（启动器搜索，前缀 `ph`）；Noctalia 声明式 UI 原语（`ui.row/label/button/slider/toggle/input`） |
| **调性** | 系统原生、克制精确、状态优先——像操作系统的一部分，而非网页应用 |
| **主题** | 暗色（Noctalia/niri 桌面语境，IDE 亦为暗色） |

### 现有界面诊断（改进依据）
1. **分区仅靠分隔线**：设备、参数、配对三段在一个滚动列表里，视觉层级弱，信息密度高却无重点。
2. **配对区常驻**：即使已连多台设备，配对表单也一直占空间，干扰主流程。
3. **参数与设备混排**：选中设备后参数直接内联在列表下方，上下文切换生硬。
4. **重命名靠右键**：可发现性低，用户不知道能改名。
5. **"投屏"反馈弱**：只有状态点 + 文字，缺少"正在投屏"的强信号。
6. **端口易混淆**（文档 §11.5）：配对端口 vs 调试端口，原界面无提示。

---

## 2. 设计原则

1. **原生融入（Native Fit）**：用桌面壳自己的空间语言（悬浮窗、卡片、状态点），不引入网页式装饰。
2. **状态优先（Status-First）**：每台设备的"在线 / 投屏中 / 离线"用颜色 + 标签双重编码，一眼可读。
3. **渐进披露（Progressive Disclosure）**：配对这类低频操作收起，参数只展示选中设备——减少默认认知负载。

## 3. 设计系统（Design Tokens）

### 3.1 色彩（暗色 · 冷中性基底 + 翠绿信号色）
> 避免"青+深蓝发光"类 AI 配色；用 oklch 构建有轻微冷调的灰阶，唯一强调色为翠绿（信号/投屏中语义，与文档既有约定一致）。

| Token | 值（oklch） | 用途 |
|---|---|---|
| `--bg-base` | `oklch(0.17 0.012 255)` | 桌面背景 |
| `--surface-1` | `oklch(0.21 0.014 255)` | 面板主体 |
| `--surface-2` | `oklch(0.25 0.016 255)` | 设备卡片 |
| `--surface-3` | `oklch(0.30 0.018 255)` | hover / 选中 / 输入 |
| `--border` | `oklch(0.34 0.015 255 / 0.55)` | 描边 |
| `--text-1` | `oklch(0.96 0.004 255)` | 主文字（对比 > 14:1） |
| `--text-2` | `oklch(0.74 0.008 255)` | 次要文字 |
| `--text-3` | `oklch(0.56 0.010 255)` | 辅助 / 占位 |
| `--accent` | `oklch(0.72 0.16 150)` | 投屏中 / 主操作（翠绿） |
| `--accent-soft` | `oklch(0.72 0.16 150 / 0.16)` | 选中底纹 / 高亮轨 |
| `--amber` | `oklch(0.80 0.14 75)` | 离线 / 配对提示 |
| `--danger` | `oklch(0.62 0.19 25)` | 停止 / 断开 |

> 对比度：正文 `--text-1`/`--text-2` 对 `--surface-1/2` 均满足 **WCAG AA**（≥ 4.5:1）；状态标签文字叠加语义色块时保证 ≥ 3:1。

### 3.2 字体与排版
- **正文字体**：系统 UI 栈（`system-ui, "Segoe UI", "PingFang SC", sans-serif`），中文用 `PingFang SC / Microsoft YaHei`。
- **技术值字体**：等宽（`"JetBrains Mono", ui-monospace, monospace`）——仅用于设备 ID、IP:端口、参数数值。这是真实技术信息，非"装饰性科技感"。
- **比例**：标题 15px/600，区段标签 11px/700 大写 + 字距，正文 13px，技术值 12px 等宽。

### 3.3 间距 / 圆角 / 海拔
- **间距标尺**：4 / 8 / 12 / 16 / 20 / 24（8pt 基准，配合 4pt 微调）。
- **圆角**：卡片 12px，控件 8px，按钮 8px，状态点圆形。
- **海拔**：面板 `0 8px 30px rgba(0,0,0,.45)`；卡片无独立阴影，靠 `--surface` 明度差 + 1px 描边区分。

### 3.4 动效
- 选中切换、展开配对：**ease-out-quart**（≈280ms）。
- 状态变化（投屏中 / 停止）：颜色过渡 200ms + 轻微缩放。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 4. 三界面设计

### 4.1 bar widget（任务栏状态图标）
- **图标**：`device-mobile`，投屏中=翠绿，空闲=中性灰（`surface_variant`）。
- **tooltip**：`手机操控：正在投屏 N 台` / `手机操控：未投屏`。
- **左键**：开/关 panel。**右键**：若有设备且未投屏，直接用最近设备+历史参数启动（保留文档原语义）。
- 改进：tooltip 显示投屏设备数量，比单纯"绿/灰"信息量更高。

### 4.2 panel（主力配置窗，380×520 悬浮居中）
**布局（自上而下）：**

```
┌─────────────────────────────────────┐
│  手机操控            2 在线 · 1 投屏中 │  ← 头部：标题 + 状态小结
├─────────────────────────────────────┤
│  设备                                │  ← 区段标签
│  ┌───────────────────────────────┐  │
│  │ 📱 Mi 14                      │  │  ← 设备卡片（选中态：左侧翠绿轨）
│  │    Wi‑Fi · 192.168.1.3:5555   │  │     右侧状态徽标 + 投屏/停止按钮
│  │            [投屏中]   [停止]   │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 🔌 Pixel 8                    │  │
│  │    USB · 在线        [投屏]    │  │
│  └───────────────────────────────┘  │
│                                     │
│  参数 · Mi 14                       │  ← 仅展示选中设备的参数
│  分辨率上限    ──●──────  1920 px    │
│  码率          ─●────────  8 Mbps   │
│  帧率上限      ──────●────  60 fps   │
│  ☑ 熄屏投屏      ☑ 录屏             │
│                                     │
│  ＋ 配对新无线设备                  │  ← 渐进披露：默认收起
│  ┌───────────────────────────────┐  │  ← 点击展开配对表单
│  │ IP:端口   [192.168.1.3:39001]  │  │
│  │ 配对码     [123456]            │  │
│  │ ⓘ 配对端口为一次性，调试端口…   │  │  ← 解决端口混淆
│  │              [配对]            │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**关键改进：**
- 设备→参数**分步呈现**：参数只显示在选中卡片下方，避免混排。
- 设备卡片自带**投屏/停止**一键操作，状态徽标（投屏中/在线/离线）三态清晰。
- 配对区**默认收起**，低频操作不干扰主流程；展开后内嵌"端口区别"提示。
- **重命名**：卡片 hover 出现 ✎ 按钮（替代难发现的右键），点击 inline 编辑，留空恢复型号——比原版更可见。
- **空状态**：无设备时显示插图 + 主 CTA「配对新设备」，有教育意义而非干巴巴一句提示。

### 4.3 launcher_provider（启动器搜索）
- 前缀 `ph`，结果卡片：`设备名` + `传输方式 · 在线/离线` + 图标。
- 选中即按该设备启动 scrcpy（保留文档语义）。
- 视觉：沿用面板卡片语言，结果项高度一致，避免"未发现设备"时孤立提示。

## 5. 交互改进对照

| 痛点（文档/现状） | 设计方案 |
|---|---|
| 分区仅靠分隔线 | 卡片化设备 + 区段标签 + 选中左轨，层级清晰 |
| 配对区常驻 | 渐进披露，默认收起，点击展开 |
| 参数与设备混排 | 选中设备后参数独立成段展示 |
| 重命名靠右键 | 卡片 hover ✎ 按钮 + inline 编辑 |
| 投屏反馈弱 | 翠绿状态徽标 + 卡片右侧一键操作 + widget 计数 |
| 配对/调试端口混淆 | 配对表单内嵌提示说明 |
| 空状态弱 | 插图 + 主 CTA 引导 |

---

## 6. 无障碍（WCAG AA）
- 文字对比度 ≥ 4.5:1（大号 ≥ 3:1）。
- 所有控件 ≥ 36px 触控高度（桌面指针目标 ≥ 32px，按钮实际 36px）。
- 状态**不只靠颜色**：投屏中/在线/离线均有文字标签 + 图标。
- 键盘可达：卡片可 Tab 聚焦，参数滑块标准 `range` 原生可操作。
- 动效尊重 `prefers-reduced-motion`。

---

## 7. 实施备注（映射到 Noctalia 声明式 UI）
- 设备卡片 → `ui.row` 内嵌 `ui.glyph / ui.label / ui.box(状态点) / ui.button`。
- 参数滑块 → `ui.slider`（保留 `onChange` 即时存参 + 重启 scrcpy）。
- 开关 → `ui.toggle`（熄屏、录屏）。
- 配对展开 → panel 局部重渲染（`render()`），控制表单显隐。
- 重命名 → 现有 inline `ui.input` 逻辑，仅将触发入口从右键改为 ✎ 按钮。
- 头部状态小结 → 订阅 `KEY_DEVICES` + `KEY_RUNNING` 聚合计算。

> 设计不改动任何后端/IPC 逻辑（`icefish/phone-operate:core` 的 `start/stop/pair/...` 事件原样保留），仅重排与美化前端呈现。
